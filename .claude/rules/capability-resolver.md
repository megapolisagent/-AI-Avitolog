# Capability Resolver

> Этот агент не проектирует и не устанавливает новых Skill/агентов сам — протокол внешней разведки (3 источника, Platform Decision Record) здесь не нужен. Разведка и решение «строить или нет» — у Engineer, после согласия владельца.

## Потребность отдельно от инструмента

Прежде чем решать, какой конкретный Skill/агент/инструмент использовать — сначала назвать класс потребности, не инструмент. Смешивание этих двух решений повышает риск выбрать привычное, а не то, что реально нужно задаче.

## Если своего скилла на это нет

Не искать, не сравнивать, не собирать самому. Назвать владелице класс потребности и то, что из установленного (`.claude/skills/`) её не закрывает — одной строкой. Согласие владелицы → задача на разведку и подключение уходит Engineer.

## Та же дисциплина — перед тем как заявить «источник недоступен»

Прежде чем написать «X недоступен» — проверить, нет ли уже готового метода, решающего ту же задачу другим путём, и не обходит ли уже разрешённый инструмент систему разрешений, в которой ищется недостающий доступ.

## Веб-доступ по умолчанию — Exa, не встроенные WebSearch/WebFetch

Для любого поиска в вебе и получения содержимого страницы — по умолчанию **Exa** (`mcp__exa__web_search_exa`/`mcp__exa__web_fetch_exa`, подключён глобально, не через `.mcp.json` этого репозитория), не встроенные `WebSearch`/`WebFetch`. Переход на встроенные — только если Exa вернула пусто/ошибку на конкретном запросе. Каталоги новостроек застройщиков в этой нише почти всегда JS-рендер — на них `WebFetch`/`WebSearch` отдают пусто, Exa рендерит корректно.

## Кэш Exa — не доверять `web_fetch_exa` для цены/live-данных

`mcp__exa__web_fetch_exa` не передаёт параметр свежести (`maxAgeHours`) и может молча отдать устаревший кэш страницы вместо живой версии — без сигнала, что это кэш, не свежий ответ. Для цены лота, статуса застройки, скидки застройщика — любого факта, который должен быть live прямо перед решением о цене публикации — результат `web_fetch_exa` не подаётся как ЗНАЮ, только как ПРЕДПОЛАГАЮ до дополнительной проверки.

Надёжный путь для live-данных — прямой запрос к Exa API с `maxAgeHours: 0` (принудительный обход кэша), не через MCP-инструмент:

```bash
curl -s -X POST 'https://api.exa.ai/contents' \
  -H "Authorization: Bearer $EXA_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"ids": ["<URL>"], "maxAgeHours": 0, "livecrawlTimeout": 12000}'
```

Firecrawl (`mcp__firecrawl__firecrawl_scrape`) — альтернатива, если подключён. Самый надёжный источник для критичной цены перед публикацией — свежий скриншот/подтверждение от владелицы, не автоматический fetch ни одним из инструментов.
