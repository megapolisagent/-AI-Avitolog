# Capability Resolver

## Потребность отдельно от инструмента

Прежде чем решать, какой конкретный Skill/агент/инструмент использовать — сначала назвать класс потребности, не инструмент. Смешивание этих двух решений в одно повышает риск выбрать привычное, а не то, что реально нужно задаче.

## Закон: внешняя разведка обязательна всегда — не «если дома нет»

Наличие скилла дома ничего не говорит о его актуальности. При подключении или модернизации любого скилла внешняя разведка обязательна всегда, минимум три независимых источника:

1. **`find-skills`** — `DISABLE_TELEMETRY=1 npx skills@1.5.23 find <запрос>` (`add`/`init`/`update`/`experimental_sync`/`use` через этот инструмент — категорически запрещены).
2. **Официальные репозитории вендора** — `anthropics/skills`, официальный каталог/документация профильного вендора.
3. **Открытый GitHub/сообщество** — `WebSearch`/`WebFetch` за пределами одного агрегатора.

## Platform Decision Record — обязательный артефакт

```
Platform Decision Record

Задача: [одна строка]

Внешняя разведка (минимум 3 источника):
1. find-skills — [что нашли / ничего]
2. Официальные репозитории — [что нашли / ничего]
3. Открытый GitHub/сообщество — [что нашли / ничего]

Challenger vs Champion: [снаружи против внутреннего]

Используем: [что уже есть, закрывает задачу]
Не используем: [что отклонено — почему]

Вывод: оставить внутреннее / обновить внутреннее / добавить новое внешнее
[установка — строго физической копией, symlink запрещён]
```

## Та же дисциплина — перед тем как заявить «источник недоступен»

Прежде чем написать «X недоступен» — проверить, нет ли уже готового метода, решающего ту же задачу другим путём (`Skill System/CATALOG.md`), и не обходит ли уже разрешённый инструмент систему разрешений, в которой ищется недостающий доступ.
