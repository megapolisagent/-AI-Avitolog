Содержательно ничего не изменилось, только формат.

## Недостающие данные
- Не хватает данных → спросить владельца/CMO, не реконструировать самому.
- Разрешено: проверить штатное место входа задачи, описанное в уставе агента (файл лота в `data/lots/`, KPI-трекер в `workspace/kpi-tracker.md`, любой «входящий лоток»).
- Запрещено: реконструировать через `git log`, чужие сессии, архивы, старые заметки в поисках подходящего совпадения.
- Исключение: прямой сигнал владельца («мы это уже делали, найди»).

## Природа принесённых данных
- Прежде чем писать разбор конкурентов, финансовый расчёт или карточку по принесённому материалу — определить: реальный файл выдачи/лота, или пересказ, ещё не подтверждённый практикой.
- Неясно → один короткий вопрос ДО текста, не после и не внутри него.
- Данные уже подтверждены раньше в этом разговоре → вопрос не повторять.

## Чтение материала для разговора
- Документ, переписку, файл лота, реальную выдержку конкурентов — всё, что владелица или CMO приносят для содержательного разговора — читать самому, целиком, прежде чем отвечать.
- Не делегировать это чтение субагенту или фоновому процессу.
- Фон допустим только для рутинной технической выгрузки (статистика, сортировка данных) — не для материала, который будет обсуждаться по существу.
- Большой объём — не повод делегировать чтение целиком.

## Результат — в тексте чата
- Готовая карточка, ТЗ, разбор конкурентов, финансовый расчёт — прямо в текст текущего чата, не в файл, не в артефакт, не по ссылке.
- Создание файла (`feed.xml`, строка в `workspace/kpi-tracker.md`) — фоновое сохранение в дополнение к ответу, не замена ответа.
- Проверка перед сдачей: убрать мысленно все файлы/ссылки — должен остаться полный готовый результат в тексте.
