# Правила памяти и самообучения

> Как агент помнит владелицу и становится точнее от раза к разу.

## Три уровня памяти

### Уровень 1 — Постоянная память (`MEMORY.md`)
Что верно ВСЕГДА. Лимит на объём, только самое главное.
- **Читать:** всегда при старте сессии.
- **Писать:** появился новый постоянный факт — дописывается сюда одной строкой.

### Уровень 2 — Дневник (`memory/ГГГГ-ММ-ДД.md`)
Хроника по дням: что делали, где остановились.
- **Читать:** последний дневник при старте.
- **Писать:** в конце сессии — итог дня.
- **Правки владелицы** — в отдельный файл `memory/feedback_<тема>.md`.

### Уровень 3 — Копилка знаний (`knowledge/`)
Механика площадки, схемы, источники данных — растёт по ходу работы.
- **Читать:** под конкретную задачу, точечно.
- **Писать:** когда накопилось что-то полезное на будущее.

## Правило дневника

Каждый новый день работы — файл `memory/ГГГГ-ММ-ДД.md`, в конце сессии три строки: **Что сделали**, **Что осталось**, **Решения**.

## Самообучение

| Когда | Куда пишем |
|---|---|
| Владелица поправила («не так», «переделай») | `memory/feedback_<тема>.md` |
| Владелица 2+ раза спросила одно и то же | нужный файл в `knowledge/` |
| Устойчивый вывод из опыта | `knowledge/lessons-learned.md` |

### Шаблон правки

```markdown
# Правка: <тема>
Дата: ГГГГ-ММ-ДД
Было: <что агент сделал не так>
Правка владелицы: <что сказала изменить>
Правильно: <как теперь делаем>
```

## Когда источники расходятся

1. **`MEMORY.md`** — курируется, предполагается актуальной; источник истины по умолчанию.
2. **Более свежая запись в `memory/`**, чем последнее обновление `MEMORY.md` — используй дневник, но допиши то же самое в `MEMORY.md`.
3. **`knowledge/`** — наименее приоритетно.

## ⚠️ Две памяти — не путать

Встроенная авто-память среды выполнения — не наша система. Наша память — только `MEMORY.md`, `memory/`, `knowledge/`.

## Память переживает любое обновление

`MEMORY.md`, `memory/`, `knowledge/` дополняются по ходу работы, но не перезаписываются шаблонами никогда.
