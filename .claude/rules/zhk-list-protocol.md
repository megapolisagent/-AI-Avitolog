# Регламент работы со списками ЖК и лотов

Применяется всегда, когда владелица передаёт список ЖК, лотов, ссылок, HTML-выгрузку — и нужна проверенная таблица по каждому объекту (для презентации, сравнения, подбора под клиента).

## 1. Зафиксировать входной список

- Выписать все полученные объекты в нумерованный список.
- Указать, сколько объектов получено.
- Работать только с этим списком, если не попросили расширить его.
- Не объединять, не исключать и не заменять объекты молча.
- Если название, ссылка или лот не читаются — пометить строку: «не удалось идентифицировать».

## 2. Пройти каждый объект по очереди

- Открыть страницу / сайт, который относится именно к этому объекту.
- Собрать только те поля, которые запрошены.
- Для каждого объекта — результат: данные найдены, данных нет или страница недоступна.
- Не завершать задачу, пока количество обработанных строк не равно количеству объектов во входном списке.
- Если часть источников технически недоступна — всё равно вернуть таблицу по всему списку и указать, по каким строкам данные недоступны.

## 3. Проверить, что источник официальный, не агрегатор

Заголовок страницы «официальный сайт» — не доказательство, это может написать любой агрегатор/реселлер (типичные признаки паразитных доменов: поддомены крупных агрегаторных платформ, сайты-визитки с чужим брендингом внутри).

Порядок проверки:
1. Открыть политику конфиденциальности / футер сайта.
2. Найти юрлицо-оператора персональных данных.
3. Сверить с юрлицом застройщика (искать отдельно, если не очевидно) и с адресом самого объекта.
4. Совпало → источник официальный. Не совпало или не названо → источник не подтверждён, помечать ПРЕДПОЛАГАЮ.

## 4. Брать точные данные

- Переносить цифры, названия, сроки, площади, цены и характеристики так, как они указаны на странице.
- Рядом с каждым объектом оставлять ссылку на страницу, откуда взяты данные.
- Если есть несколько вариантов — не выбирать один самостоятельно: перечислить их или спросить, как отбирать.
- Не заменять отсутствующие данные предположением.
- Не рассчитывать значения самостоятельно, если не попросили отдельно.
- Не использовать источник одного объекта для данных другого объекта.

## 5. Комнатность — по факту планировки, не по названию

Число в названии планировки на сайте застройщика обычно считает **спальни**, а не все помещения — кухня-гостиная в счёт часто не идёт, даже если в названии есть слово «евро». Но конвенция подсчёта своя у каждого сайта, и одинаковое слово в названии у разных застройщиков может означать разное число спален. Перенос логики одного застройщика на другого недопустим.

Если задача касается планировки:
- если у сайта есть фильтр по числу спален — использовать его напрямую, не фильтр «комнатность»;
- если фильтра нет — не отсеивать лоты по подписи комнатности, идти к плану;
- открыть план конкретного лота, смотреть на само изображение, а не на название фильтра или текст карточки;
- посчитать вручную: закрытые спальни (комнаты с кроватью на плане) отдельно от кухни-гостиной (комната с плитой/обеденным столом — считается одним помещением, не спальней);
- указать только фактически видимые на плане помещения;
- если план не открылся — написать: «планировка не проверена».

Если план не текстовый, а изображение на внешнем сайте — скачать файл локально и открыть, а не полагаться на подпись рядом с картинкой.

## 6. Визуалы

- Сохранять ссылку на конкретное изображение.
- Подписывать, что именно изображено: фасад, территория, генплан, планировка или интерьер.
- Не подменять визуал одного объекта визуалом другого.

## 7. Надёжность застройщика

Минимум два независимых источника (например: рейтинговый агрегатор по срокам сдачи + форум отзывов дольщиков), не только официальный сайт застройщика. По возможности — отзывы про конкретный объект, не только про застройщика в целом. Если источники расходятся в цифрах — показывать оба, не выбирать удобный.

## 8. Парк и транспортная доступность

Название конкретной зелёной зоны/остановки + время пешком + источник. Если время не указано точно застройщиком — помечать ПРЕДПОЛАГАЮ, не досчитывать самостоятельно.

## 9. Контроль перед ответом

Перед финальным ответом проверить:
- число строк в результате равно числу объектов во входном списке;
- у каждой строки есть статус: найдено / не найдено / недоступно;
- ссылка относится именно к объекту в строке;
- нет предположений, выданных за данные сайта;
- нет пропущенных объектов.

В начале ответа всегда указывать:
«Получено объектов: N».
«Обработано объектов: N из N».

Если N не равно N — сначала показать непроверенные строки и причину.

## Итоговый набор данных на один объект

| Поле | Требование |
|---|---|
| Официальный источник | Домен + подтверждение юрлица (п.3) |
| Лот | Этаж / площадь / цена (с акцией и без) / № квартиры / корпус |
| Планировка | Ссылка на план + подтверждённое число спален (п.5) |
| Застройщик | Название + рейтинг из ≥2 источников + известные проблемы по конкретному объекту, если есть |
| Парк | Название + время пешком + источник |
| Метро | Название + время пешком |
| Пометки неопределённости | Явно указано, где данные ПРЕДПОЛАГАЮ, а не ЗНАЮ |

## Технические заметки по инструментам

- JS-фильтры на сайте (клик по вкладке типа «2 спальни»), которые не даются через обычный клик по CSS-селектору: искать элемент по точному тексту через выполнение JS-скрипта на странице, обёрнутого в самовызывающуюся функцию.
- Если клик по фильтру подгружает весь каталог и результат не помещается в ответ целиком — он сохраняется в файл; доставать нужные строки точечным поиском по файлу, не читать файл целиком.
- Чтобы посмотреть план с внешнего сайта, если текстовых размеров комнат нет — скачать картинку в рабочую папку и открыть её напрямую, а не полагаться на подпись рядом.
