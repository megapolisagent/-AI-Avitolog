# CRO Auditor

Критерии приёмки для карточки-локомотива Avito — не полноценный CRO-аудит сайта/воронки (нет форм, чекаута, email-капчура в этом продукте), а адаптация двух реально переносимых частей исходного скилла: LIFT-модель для оценки текста и ICE для приоритизации правок.

## Heuristic Evaluation (LIFT Model)

Оцени первый экран карточки (заголовок + первые строки описания) по 6 осям:

| Фактор | Вопрос | Влияние |
|--------|--------|---------|
| **Value Proposition** | Понятна ли выгода конкретно для сегмента покупателя (семья/инвестор/наличные)? | + |
| **Relevance** | Совпадает ли текст с тем, что искал покупатель (поисковой запрос, район, метраж)? | + |
| **Clarity** | Понятно ли с первого прочтения, что это за лот и какой следующий шаг? | + |
| **Urgency** | Есть ли реальная (не выдуманная) причина писать сейчас — реальная акция/срок? | + |
| **Anxiety** | Есть ли у покупателя недосказанные опасения (цена, этаж, застройщик), которые текст не снимает? | − |
| **Distraction** | Отвлекает ли что-то от главного посыла (лишние детали, неструктурированный текст)? | − |

## Чек-лист карточки

- [ ] Выгода для конкретного сегмента видна в первых 1-2 строках, не общая фраза
- [ ] Заголовок использует конкретную деталь (цена/метраж/район), не «квартира в продаже»
- [ ] Единственный явный призыв к действию (написать в чат/позвонить) — не два конкурирующих
- [ ] Цифры в тексте (цена, платёж, срок) совпадают с данными лота, ничего не выдумано — сверка через `avito-listing-packaging/tools/validate_listing.py`, не на глаз ещё раз
- [ ] Возражение по цене/условиям снято текстом (почему цена такая, что входит), не оставлено висеть

## Прioritization — ICE Score

| Dimension | Definition | Scale |
|-----------|-----------|-------|
| **Impact** | Насколько правка повысит отклик? | 1-10 |
| **Confidence** | Насколько уверены, что сработает? | 1-10 |
| **Ease** | Насколько легко внести правку? | 1-10 |

**ICE Score** = (Impact + Confidence + Ease) / 3 — используй для сортировки правок, если их больше одной-двух.

## Формат замечания

```
**Проблема:** [что не так]
**Место:** [заголовок/первый экран/цена/CTA]
**Влияние:** [ВЫСОКОЕ/СРЕДНЕЕ/НИЗКОЕ]
**Почему:** [какой пункт LIFT/чек-листа нарушен]
**Правка:** [конкретная замена текста]
**ICE:** [X/10]
```

## Вне скоупа

Funnel-анализ (Awareness→Retention, воронка signup/onboarding), метрики форм/чекаута, SaaS/e-commerce бенчмарки конверсии, A/B-тестирование с расчётом выборки, email opt-in/capture-метрики — у одной карточки на классифайде нет ни форм, ни чекаута, ни email-воронки.

## Применимость у Avitolog

`avito-listing-packaging` (карточка-локомотив как объект аудита), `listing-copywriter` (текст, который проверяет LIFT-модель выше).

## Формат вывода для Quality Gate Авитолога

Обязательный формат, когда `cro-auditor` вызывается как гейт перед статусом `У CMO` (`avito-listing-packaging/SKILL.md`, шаг 3.5) — не разовое замечание, а полный отчёт с итоговым вердиктом:

1. **Поисковый сценарий и сегмент** — для кого и под какой запрос написана карточка (из портрета покупателя/брифа `pain-point-extractor`, не домысел).
2. **Первый экран (150–180 символов) — что покупатель должен понять** — прямая цитата этого фрагмента + оценка, понятно ли с одного прочтения.
3. **Проверка первого экрана** — `PASS`/`FAIL`.
4. **Главный подтверждённый факт-доказательство ценности** — конкретная цифра/условие из данных лота, не общая фраза.
5. **Value proposition** — `PASS`/`FAIL` (понятна ли выгода конкретно для сегмента).
6. **Один CTA** — `PASS`/`FAIL` (ровно один явный призыв, не два конкурирующих).
7. **Неподтверждённые факты / общие оценки / штампы** — списком, с указанием, где именно в тексте.
8. **Соответствие пути клиента** — `PASS`/`FAIL`.
9. **Итоговый статус** — `PASS` / `REVISE` / `BLOCK` + перечень обязательных правок для `REVISE`/`BLOCK`.

**`BLOCK` обязателен**, если выполняется любое из: в первом экране нет ясного объекта и факта; есть неподтверждённое обещание/цифра; есть самопрезентация брокера в карточке первичного рынка; два или больше CTA; текст не соответствует поисковому сценарию.

Цикл: `listing-copywriter` → этот отчёт → при `REVISE`/`BLOCK` возврат в `listing-copywriter` с этими же правками → повторный прогон `cro-auditor` на новой версии → только `PASS` пропускает карточку дальше по пайплайну.
