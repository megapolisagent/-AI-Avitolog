# Listing Copywriter

## Вход

Условия объекта (ЖК, планировка, площадь) + сегмент/портрет покупателя (кто это, что для него главное — семья ищет метраж и школу рядом, инвестор — доходность и ликвидность, покупатель с наличными — скорость сделки и скидку) + **бриф от `pain-point-extractor`** (`workspace/<ЖК>-<дата>-brief.md`), если разведка рынка уже запускалась по этому ЖК — рычаг убеждения и формула подачи оттуда, не придумывать заново своим чутьём. Брифа нет — писать по правилам ниже без него, не блокировать карточку. Финансовые цифры (цена/ПВ/платёж) — готовыми из `listing-fin-offer`, не пересчитывать самому.

## Правила живого текста, не шаблона

Если текст можно вставить в любую другую карточку без изменений, значит он не готов:

- **Банк-лист запрещённых слов** — если слово из списка попало в текст, переписать до того, как отдать результат: «прекрасный», «уникальный», «идеальный», «не упустите шанс», «звоните прямо сейчас», «развитая инфраструктура», «динамично развивающийся район», «выгодные условия», «широкие возможности», «продуманная планировка» — общие слова без факта за ними, любая карточка застройщика их использует. Автоматическая проверка — `.claude/skills/listing-copywriter/tools/check_banned_patterns.py` (см. ниже).
- **Полная лексическая матрица и голос бренда** — `references/tone-of-voice-bogolyubova.md` (антисловарь, регистры речи, правило точности) и `references/brand-book-bogolyubova.md` (JTBD, позиционирование, УТП). Физическая копия из `C:\Users\bogol\OneDrive\Рабочий стол\Бренд и позиционирование\` — при обновлении источника сверить и обновить здесь же.
- **Тактика и структура** — `references/konversionnyy-pleybuk-megapolis.md` (заголовки, Value Framing, честные механизмы дефицита, CTA-библиотека). При конфликте с TOV — TOV побеждает.
- **Спецмодуль Avito** — `references/avito-spetsmodul.md` (формула сниппета 150–200 символов, блочная структура тела объявления, оформление). Порядок первого экрана — по уже действующему правилу этого файла ниже (финансовый расчёт первым) или по блочной логике спецмодуля (локация первой) — **решает Авитолог сам**, у него полный контекст практики по площадке; спецмодуль не переопределяет правило ниже автоматически.
- **So What? Chain — по зоне, не по факту в отдельности.** Сначала собери все факты одной зоны квартиры (кухня-гостиная, спальни, санузлы, вид), каждый прогони через «и что?» до реальной выгоды — но в карточку выведи одно слитное предложение-сцену на зону, не цепочку «факт, и это значит...» по каждому факту подряд. Не «кухня-гостиная 16 м². И что? Готовите не теряя из виду гостиную» (факт + пристёгнутый вывод), а «На кухне-гостиной 16 м² готовите, не теряя из виду гостиную» (вывод растёт из факта, а не приклеен к нему). Признак сбоя — швы-переходники между фактом и выводом («а значит», «что даёт», «то есть», «так что»): если предложение можно разрезать по такому шву на «характеристика» + «объяснение зачем», это ещё список фактов с довеском, не сцена — переписать.
- Выгода для этого конкретного покупателя, не абстрактная: не «выгодные условия», а что это меняет именно для семьи/инвестора/покупателя с наличными.
- Одна конкретная эмоция или деталь, которая цепляет («вид на парк из окна кухни», не «прекрасный вид»), не список характеристик.
- Призыв — конкретное действие («Напишите +, пришлю...»), не «звоните».
- **Служебные пометки проверки данных в клиентский текст не идут.** Формулировки вида «по данным сайта застройщика», «на момент проверки», «требует уточнения» — это язык рабочего файла лота (`data/lots/`), не карточки для покупателя. Условие названо один раз простыми словами («при 100% оплате или ипотеке без субсидии»), без юридического нанизывания квалификаторов подряд («действует при этих условиях, максимальная, не суммируется с другими акциями и скидками» — это цитата с сайта застройщика для проверки факта, не блок клиентского текста).

## Структура

1. **Первый экран текста** — финансовый расчёт (цифры уже посчитаны `listing-fin-offer`, здесь только подача): полная цена, ПВ (сумма и %), условия рассрочки/ипотеки, ежемесячный платёж если есть график. Без абзацев про инфраструктуру и локацию — это не первый экран.
2. **Призыв к лид-магниту** — конкретное предложение с действием, банк форматов по сегменту — `.claude/skills/lead-magnets/SKILL.md`.
3. **ТЗ на фото-карусель**, не только обложку: обложка (плашка + рендер/планировка с размерами, не типовой фасад), дальше по порядку — зонирование/габариты комнат, вид из окна, архитектура/лобби, инфраструктура двора, схема платежей/график (если есть). Текст на плашках крупный, читаемый со смартфона; никаких контактных данных на самом фото.

## Скрипт чат-воронки

Первый автоответ (лид-магнит из банка форматов), 1-2 уточняющих вопроса для квалификации, финальный шаг — увести на звонок/WhatsApp. Короткие реплики, не абзацы. Главный финансовый триггер — из первого экрана выше. Сегмент не известен и не спрошен — не выбирать за владелицу, дать нейтральный вариант и явно спросить.

## Второй проход — критик, обязателен перед выдачей

После того как текст написан — перечитать отдельным проходом именно как критик, не автор:
1. Есть ли слово из банк-листа — если да, переписать.
2. Есть ли хоть один факт, прошедший через So What? Chain до реальной выгоды, не сырая характеристика — если нет, вернуться и доделать.
3. Можно ли этот текст вставить в карточку другого ЖК без изменений — если да, недостаточно конкретно, переписать.
4. Читается ли текст как одна сцена/история о жизни в этой квартире, а не список фактов с пристёгнутыми выводами — вслух найти швы-переходники («а значит», «что даёт», «то есть», «так что») между характеристикой и её объяснением; если шов виден, это ещё список, не текст — переписать по зонам, не по фактам.
5. Есть ли в тексте служебная пометка проверки данных («по данным сайта», «на момент проверки», «требует уточнения») или юридическое нанизывание условий скидки подряд («действует при... максимальная, не суммируется с...») — если да, убрать, это язык рабочего файла лота, не карточки.

Не выдавать текст с первого прохода без этой проверки. После критика — прогнать через `ru-text-critic/SKILL.md` (кальки, ИИ-штампы, канцелярит и регистр речи по-русски) и через `tools/check_banned_patterns.py` (детерминированная проверка банк-листа + канцелярита, не полагаться только на собственное суждение).

## Если данных не хватает

Плейсхолдер и прямое указание, чего не хватает (график платежей, точная площадь, портрет покупателя) — не выдуманное число и не нейтральный текст «для всех».
