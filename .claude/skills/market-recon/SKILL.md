# Market Recon

> Перенесено из `avito-listing-packaging/SKILL.md`, «Модуль 5 — Разведка рынка» — разбито по Правилу 3 Anthropic, 2026-09-14 (тот же критерий, по которому уже разбиты Модули 1/3/4 на `listing-fin-offer`/`listing-seo-geo`/`listing-copywriter`, 2026-09-10). Содержание не изменилось, только формат.

## Вход

Целевой ЖК + локация + комнатность (не весь ЖК разом). Готовый файл выдачи не обязателен — штатный запуск по запросу, не опция «если принесут».

## Полная цепочка — три шага, три разных исполнителя, каждый со своим контрактом

1. **`market-analyst`** (`.claude/agents/market-analyst.md`, вызов через `Agent`) — собирает две таблицы: А (топ-10 конкурентов-новостроек в локации + 2 смежные территории, тот же класс/метраж) и Б (целевой ЖК целиком — первичка и вся вторичка). Классифицирует продавца и ремонт, тянет текст объявления в таблицу сразу. Не оценивает, не рекомендует — правила и юридическая граница (`knowledge/apify-competitor-scraping-scope.md`) уже внутри его файла, не пересказывать здесь повторно.
2. **`scripts/market_snapshot_analyzer.py`** (детерминированный код, не агент) — считает то, что не требует суждения: дедупликацию вторички, цену мин/медиану/макс, «устарело» (только вторичка). Пороги — `config.json`, не в коде и не в голове агента. Сравнение с эталоном застройщика убрано 2026-09-17 вместе с ЖК Алия — эталона сейчас физически нет, появится новый — добавлять заново отдельным решением.
3. **`pain-point-extractor`** (`.claude/agents/pain-point-extractor.md`, вызов через `Agent`, после шага 1) — берёт тексты из обеих таблиц, отдаёт бриф (боли + рычаг убеждения + формула подачи + ключевая эмоция) в `workspace/<ЖК>-<дата>-brief.md`. Это обязательный вход для `listing-copywriter`, когда есть данные конкурентов — не пропускать молча.

**Если файл уже дан** (`data/market_raw/`, сохранённая выдача) — субагентов заново не вызывать, прогнать скрипт напрямую по этому файлу; `pain-point-extractor` всё равно вызывается отдельно, если нужен бриф под текст.

**Обработка сырой выгрузки (HTML/CSV) до и после скрипта — постоянный регламент**, не разовое суждение: `references/market-raw-data-regulation.md`. Фильтрация нерелевантных карточек (не тот ЖК, аренда вместо продажи) и проверка условности скидки застройщика — шаги, которые скрипт сам не делает, ответственность на том, кто готовит файл и читает отчёт.

**Формат таблиц — фиксированный, не придумывается заново каждый раз.** Ровно то, что отдаёт `render_markdown_table()` в скрипте — редактировать колонки только через отдельное решение владелицы, не по ходу разбора.

## Аудит по 6 пунктам (основной агент, не субагенты — нужен контекст лота владелицы для сравнения)

1. Заголовок — чем цепляет (цена/скидка/локация/УТП).
2. Первые 3 строки описания — какой триггер там главный.
3. Тип цены — реальная стоимость или заниженный платёж по ипотеке/рассрочке.
4. Финансовые триггеры — рассрочка 0%, транши, субсидия, трейд-ин, «только сегодня».
5. Визуальные крючки — что на обложке (если данные содержат описание фото, не только текст).
6. Пробелы — чего у конкурентов нет вообще → это место для УТП владельца.

## Что не делает

Не пишет текст карточки (это `listing-copywriter`), не считает финансовый оффер (это `listing-fin-offer`), не решает пул карточек/платные форматы (это `media-plan`).

## Выход

**Итог — сначала рекомендация простым языком, таблица подкрепляет её, не заменяет.** Первым — 3-5 пунктов: с какой ценой, финансовым расчётом (`listing-fin-offer`) и стратегией продвижения (`media-plan`) заходить в выдачу и почему, без цифр из 12 колонок таблицы в этих пунктах — только вывод. Таблица целиком — следом, как подтверждение цифрами, не первым, что видит владелица. Раздатый голый расчёт без прочитанного вывода — не выполненная задача, тот же принцип, что `.claude/rules/data-discipline.md` («Результат — в тексте чата»: главный ответ — в тексте, не по ссылке), только применённый не к каналу доставки, а к языку внутри самого текста. Рекомендация — вход для решения владелицы: сам не публикует лот и не меняет цену по своей инициативе (`CLAUDE.md` §3, §8).
