# Регламент обработки сырых выгрузок (HTML/CSV) для анализа рынка

> Постоянный стандарт. Полный текст регламента — зеркало на стороне CMO: `AI Marketing Strategist/.claude/skills/marketing-strategy/references/market-raw-data-regulation.md`. Этот файл добавляет привязку к реальному пайплайну (`market-analyst`, `parse_avito_html.py`, `market_snapshot_analyzer.py`) — что из 4 шагов уже автоматизировано, что пока держится на суждении агента. Держать оба файла синхронно при следующей правке любого из них.

## Когда применяется

Файл с поисковой выдачей (Apify-дамп, сохранённый владелицей HTML, CSV) — Модуль 5 (`avito-listing-packaging/SKILL.md`), исполнитель — `market-analyst` (`.claude/agents/market-analyst.md`), затем `scripts/market_snapshot_analyzer.py`.

## Шаг 1 — Фильтрация и очистка

**Дубли — уже автоматизировано.** `market_snapshot_analyzer.py` схлопывает дубли по порогам `config.json` (`duplicate_area_tolerance_m2`, `duplicate_price_tolerance_pct`) — не пересчитывать руками.

**Некорректные цены/площади — не автоматизировано вообще.** Сравнение с эталоном застройщика (`fake_threshold_pct`) не работает — эталона сейчас физически нет. Откровенно битые значения (0, пусто, опечатка на порядок) — отсеивать руками, не пропускать в файл для скрипта. Появится новый эталон под другой ЖК — добавлять сравнение заново отдельным решением, не восстанавливать прежние цифры.

**Объекты не по целевому ЖК/адресу/типу сделки — НЕ автоматизировано, ответственность агента, собирающего срез.** Ни `market-analyst`, ни `scripts/parse_avito_html.py` сейчас не фильтруют по релевантности — `parse_avito_html.py` вытаскивает всё, что нашёл в HTML, без разбора. Avito подмешивает в сохранённую страницу рекомендации по другим комплексам и аренду вместо продажи — скрипт честно посчитает их как есть, если не отсеять до запуска.

Зафиксировать явно перед запуском скрипта: сколько карточек было в файле и сколько осталось, с разбивкой причин отсева (дубль / доля / битая цена-площадь / не тот ЖК-адрес / не та сделка).

## Шаг 2 — Разметка по типу продавца (3 корзины)

Метод классификации (бейдж / косвенные признаки — рейтинг+отзывы, формулировки «от собственника»/«от застройщика X» в третьем лице) уже описан в `market-analyst.md`, п.6 — не переоткрывать здесь. `market_snapshot_analyzer.py` держит строгий словарь `SELLER_TYPE_FORM = {developer, agent, owner}` — значение вне словаря или пропущенное не отбрасывает лот, попадает в счётчик «не определено».

**Уровень уверенности (подтверждено/предположительно) — НЕ в текущей форме данных.** Ни `market-analyst.md`, ни скрипт сейчас не различают «увидел бейдж» и «предположил по тексту» — оба варианта дают одно и то же значение `seller_type`, хотя категория «застройщик» по тексту иногда на деле оказывается переуступкой. До отдельного решения о расширении схемы данных — `market-analyst` называет уверенность прямо в тексте ответа рядом со спорным лотом, не тихо кладёт его в чистую категорию.

## Шаг 3 — Сводная коммерческая таблица

**Не то же самое, что `-table.md` скрипта.** `render_markdown_table()` в `market_snapshot_analyzer.py` — фиксированный формат по комнатности (менять нельзя без отдельного решения владельца): группировка по `rooms`, колонки продавцов внутри группы, цена мин/медиана/макс. Таблица этого регламента — другой разрез, по категории продавца целиком, с диапазоном площадей и «самым дешёвым прямым аналогом» — синтез поверх `-report.json`/`-lots.json` скрипта, который собирает `market-analyst` (или тот, кто читает результат), не то, что скрипт печатает сам.

| Категория продавца | Кол-во лотов | Площадь мин-макс | Цена мин-макс | Средняя цена за м² | Самый дешёвый прямой аналог |
|---|---|---|---|---|---|

Обязательно вне таблицы: дата среза (по дате файла) и путь к исходному сырому файлу (`data/market_raw/<ЖК>-<дата>-raw.json` или аналог).

Поля, которые физически не извлекаются (типовой случай — Avito обрезает описание до 256 символов при сохранении HTML владелицей, планировка/состав комнат не долистывает, см. `market-analyst.md` п.3.2) — помечать явно «НЕТ ДАННЫХ», не оставлять пустыми и не досочинять.

## Шаг 4 — Шорт-лист прямых альтернатив (2-3 объекта)

Максимально близкие к целевому лоту: площадь, состояние, готовность документов, ссылка. Источник — уже собранная таблица Б (`market-analyst.md`, п.3), не новый сбор данных.

## Сквозное правило — условная скидка застройщика

На любом шаге, где встречается цена от застройщика: проверить, не условная ли это скидка (100% оплата / конкретный тип ипотеки), которая может не действовать при реально предлагаемом покупателю виде финансирования. Не передавать отображаемую цену в `listing-fin-offer` как окончательную без этой проверки — скидка застройщика может не действовать при семейной ипотеке или другом реально предлагаемом виде финансирования, что ведёт к неверному расчёту платежа в карточке.

## Формат выдачи

Строго таблица и краткий шорт-лист, без кода скриптов и технических логов — тот же принцип, что уже в `avito-listing-packaging/SKILL.md`, Модуль 5: «сначала рекомендация простым языком, таблица подкрепляет её, не заменяет».
