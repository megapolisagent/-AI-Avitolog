### 2026-09-04 — Приоритет «первая волна из 10 карточек» снят; роль расширена на аналитику/звонки/отзывы/спецпредложения

Статус: Locked (владелец, прямое слово — «примени все его функции... аналитика рынка нужны уже сейчас»)
Контекст: сборка 2026-09-01 зафиксировала Locked-приоритет «первая волна из 10 опубликованных
карточек, не полнота процесса. До неё — никаких новых Skills» (`HOME.md`, строка 5). Глубокий
аудит `knowledge/reference/` показал: 6 из 9 официальных API-схем, реально загруженных в дом,
никогда не были подключены в код — calltracking, отзывы/рейтинг, спецпредложения в чате,
расширенная аналитика по объявлениям, расходы на продвижение, аналитика по недвижимости.
Решение: приоритет «10 карточек» снят явным словом владельца. В `avito_api_client.py` реально
реализованы и проверены живыми вызовами: `get_rating_info`, `get_reviews`, `answer_review`,
`delete_review_answer`, `get_calls`, `get_call_by_id`, `get_call_record`, `get_items_analytics`,
`get_spendings`, `get_offers_available`, `get_offers_stats`, `get_offers_tariff_info`,
`create_offers`, `confirm_offers`, `get_market_price_correspondence`, `create_realty_report`.
Найдено и исправлено по ходу два реальных бага (не гипотетических): (1) `_request()` не
выставлял `Content-Type: application/json` ни для одного метода с телом запроса — все методы
с JSON-телом падали на `400 invalid content type`; исправлено централизованно, не по одному
вызову. (2) `_save_raw_log()` падал с `OSError` на именах файлов, содержащих RFC3339-таймстамп
с `:` — запрещённый символ в имени файла на Windows; исправлено санитизацией имени.
Подтверждено живыми вызовами на реальном аккаунте (не мокано): `get_rating_info`, `get_reviews`,
`get_offers_tariff_info`, `get_offers_stats`, `get_calls`, `get_call_by_id`, `get_items_analytics`,
`get_spendings` — все вернули настоящий ответ сервера (200). `get_call_record` — настоящий
`403 forbidden` (эндпоинт технически недоступен на этом токене/скоупе, не баг клиента).
`get_offers_available` — настоящая `400 empty itemIds` на пустом списке (валидация сервера
работает как надо). `get_market_price_correspondence`/`create_realty_report`/полный
`get_offers_available` с реальными ID — **не протестированы: на аккаунте сейчас 0 активных
объявлений**, нужен хотя бы один реальный `item_id`.
Мутирующие методы (`answer_review`, `delete_review_answer`, `create_offers`, `confirm_offers`) —
код написан и синтаксически проверен, живым вызовом НЕ протестированы намеренно (реальное
публичное действие — ответ на отзыв, отправка предложения покупателю), вызывать только по
явному решению владельца о конкретном содержании.
Обоснование: то же самое расхождение «документы загружены, роль их не использует», которое
владелец поймала лично, спросив «где они» — прямой повод не откладывать дальше.
Источник: диалог с владельцем 2026-09-04 (сессия ENGINEER).

### 2026-09-04 — Хостинг feed.xml: собственный GitHub-репозиторий + raw-ссылка, не GitHub Pages/S3

Статус: Locked
Контекст: при сборке Авитолога (2026-09-01) честно зафиксирован пробел — «хостинг feed.xml не
выбран, три варианта (GitHub Pages / S3-совместимое хранилище / сайт застройщика)»
(`ENGINEER/workspace/2026-09-01-статус-трафик-менеджер.md`). Владелец нашла и показала реальный
работающий прецедент той же задачи — `github.com/esstsu-bot/avito-feed`: обычный публичный
GitHub-репозиторий, `feed.xml` собирается скриптом из отдельных JSON-файлов по объявлению +
общий конфиг контактов, в личном кабинете Avito Pro как источник автозагрузки указана прямая
ссылка на raw-файл (`raw.githubusercontent.com/.../feed.xml`) — без отдельного хостинга,
без GitHub Pages, без S3.
Решение: тот же механизм — обычный git-репозиторий + `raw.githubusercontent.com`-ссылка,
подключённая в личном кабинете Avito Pro как источник для автозагрузки. Не GitHub Pages
(избыточно — нужен только сырой файл, не веб-страница) и не S3 (лишняя инфраструктура и
стоимость там, где GitHub решает задачу бесплатно и с готовым реальным прецедентом).
Обоснование: единственная причина, по которой решение откладывалось — отсутствие проверенного
рабочего примера именно такой схемы для автозагрузки Avito; теперь такой пример есть и найден
владельцем напрямую, не выведен теоретически.
Что не решено этим ходом: создание самого репозитория (в чьём GitHub-аккаунте, публичный или
приватный доступ к raw-ссылке — приватный репозиторий не даёт прямого raw-доступа без токена,
это отдельный практический шаг) — решается отдельно, не автоматически этой записью.
Источник: диалог с владельцем 2026-09-04 (сессия ENGINEER); `github.com/esstsu-bot/avito-feed`.

### 2026-09-01 — Официальный Avito API (включая Realty Analytics) ≠ парсинг; внешние скрапинг-сервисы (Apify и аналоги) остаются запрещены

Статус: Locked
Контекст: Engineer ошибочно смешала два разных понятия — запрет на несанкционированный HTML-парсинг чужих объявлений и легальный официальный API Avito. Владелица поправила прямо: официальный API (в т.ч. `knowledge/reference/03_analytics_market/avito-api-realty-analytics.json`, метод `marketPriceCorrespondence`) — тот же класс канала, что уже разрешён записью выше (Автозагрузка/Авторизация/Продвижение), не парсинг. Отдельно владелица предложила закрыть сбор данных конкурентов через внешний облачный сервис Apify — проверено прямым чтением `docs.apify.com/legal/general-terms-and-conditions`: Apify явно возлагает ответственность за соблюдение правил целевого сайта на пользователя, не берёт её на себя (та же находка, что раньше по OpenClaw) — смена вендора не меняет, кто нарушает соглашение Avito.
Решение: (а) официальный Avito API, включая Realty Analytics/marketPriceCorrespondence — разрешён как рабочий инструмент, тот же принцип «свой аккаунт, официальный канал», что и остальные подтверждённые эндпоинты; честная техническая граница — метод работает только с уже опубликованным объявлением владелицы (нужен existing itemId) и требует платной подписки «Лидер» в категории «Недвижимость» (не подтверждено, есть ли она у владелицы) — не даёт предпубликационного среза по чужим лотам. (б) Любой внешний скрапинг-сервис (Apify Actor и аналоги), нацеленный на сбор чужих объявлений с Avito — запрещён тем же решением от 2026-08-31/09-01, смена инфраструктуры-исполнителя не меняет юридическую суть действия.
Обоснование: различение — не по инструменту (свой код / чужой облачный сервис / headless-браузер), а по объекту действия (свой аккаунт через разрешённый канал vs чужие данные без разрешения площадки) — этот принцип теперь явно, а не только подразумевался.

### 2026-09-01 — Уточнение: официальный Avito API (Автозагрузка, Авторизация, Продвижение) разрешён; парсинг и обход защиты — по-прежнему нет

Статус: Locked
Контекст: решение от 2026-08-31 («Прямой доступ Авитолога к Avito закрыт полностью») писалось в ответ на три попытки владельца обойти отсутствие доступа нелегальными методами — API без официального подтверждения, headless-браузер с эмуляцией пользователя, капча-сервисы. С тех пор реально подтверждено официальными файлами от Avito (Swagger 3.0, скачаны владельцем из личного кабинета разработчика, `knowledge/reference/avito-api-authorization-swagger.json`, `avito-api-promotion-swagger.json`) — существует официальный API для управления СВОИМ аккаунтом (Авторизация client_credentials, Продвижение услуг), и официальный механизм «Автозагрузка» для публикации СВОИХ объявлений файлом (`instructions/avito-official-api-status.md`, прямой fetch `support.avito.ru/articles/4341`). Это не парсинг чужих данных и не обход защиты — официальные партнёрские каналы, с реальными ключами, выданными Avito на аккаунт владельца.
Решение: разрешено использовать эти официальные каналы для работы со СВОИМ аккаунтом владельца — генерация `feed.xml` по схеме Автозагрузки, вызовы Authorization/Promotion API, автоответы через Messenger API (`.env`, `avito_messenger_client.py`, `instructions/avito-integration-spec.md`). Решение от 2026-08-31 **сужено, не отменено**: по-прежнему полностью запрещено — (а) любой парсинг/сбор данных о чужих объявлениях/конкурентах на Avito любым способом, (б) обход антибот-защиты (headless-браузер с эмуляцией, капча-сервисы), (в) `send_auto_reply` живым покупателям через ещё официально не подтверждённые endpoint'ы Messenger API без предварительной ручной проверки трёх более дешёвых вызовов (`--check-token` → `--check-self-id` → `--check-chats`), не пропускать шаги.
Обоснование: факты изменились с 2026-08-31 — тогда официальных каналов не было подтверждено вообще, сейчас два из трёх (Авторизация, Продвижение) подтверждены реальными файлами от Avito, третий (Messenger) — только текстом, не тем же уровнем доказательства. Решение обновляется вслед за фактами, не потому что старая запись «мешает» цитироваться агентом — старая запись не удаляется, история решений в этом файле не переписывается (см. шапку файла).
