# Спецификация: автозагрузка (feed.xml) + Messenger API

Статус: спецификация архитектуры, не рабочий код. Часть деталей ждёт подтверждения от владельца (см. `avito-official-api-status.md`) — не додумана вместо подтверждения.

## Модуль 1 — Генератор feed.xml (Автозагрузка)

**Механизм подтверждён официально** (`support.avito.ru/articles/4341`) — Avito сам читает файл по URL на своём расписании, публикация/обновление автоматические после этого шага.

Поток:
1. Владелец утверждает текст карточки (Модуль 1 `avito-listing-packaging`).
2. Утверждённый пакет конвертируется в один `<Ad>`-блок и добавляется/обновляется в `data/feed/feed.xml`.
3. `feed.xml` должен быть доступен Avito по стабильному URL — **файл на локальном диске Avito не увидит**, нужен хостинг (даже простой статический — GitHub Pages/S3/любой веб-сервер). Это не решено этим документом — отдельный вопрос владельцу, не решается тихо.
4. Подтверждённый реальный тег — `<AvitoId>` (для связки с уже опубликованным объявлением). Полная схема тегов (`<Price>`, `<Address>` и т.д. — упомянуты сторонними источниками, НЕ Avito напрямую) — `[УТОЧНИТЬ]`, ждёт реального шаблона из личного кабинета («Автозагрузка» → шаблон).

**Что можно строить прямо сейчас, не дожидаясь схемы:** сам конвейер «утверждено → попадает в очередь на фид» — да. Финальную сериализацию в правильные XML-теги — только после реальной схемы, иначе Avito может отклонить файл целиком или его часть.

## Модуль 2 — Messenger API (чаты, автоответы, статусы)

**Подтверждено:** портал `avito.ru/developers` реален, в каталоге есть Messenger API. OAuth2 client-credentials — стандартный, общеизвестный паттерн (не специфика Avito, общее знание про OAuth2).

**Не подтверждено, `[УТОЧНИТЬ]`:** точный token endpoint, base URL API, формат запроса на отправку сообщения/чтение чата, формат статуса объявления. Не беру эти детали из найденного стороннего `github.com/MissiaL/avito-api` — тот источник помечен как не заслуживающий доверия (`avito-official-api-status.md`).

Учётные данные — `.env` (реальные значения, не в git), `.env.example` (структура, безопасно коммитить):
- `AVITO_CLIENT_ID` — получен, сохранён.
- `AVITO_CLIENT_SECRET` — получен, сохранён.
- `AVITO_TOKEN_URL`, `AVITO_API_BASE_URL` — `[УТОЧНИТЬ]`.

Три заявленные функции — план, реализация ждёт endpoint'ы:
1. **Получение входящих сообщений** — вероятно webhook или polling, зависит от реального API (webhook — Avito сам шлёт нам, polling — мы сами спрашиваем по расписанию); какой из двух реально поддерживает Messenger API — не знаю, не гадаю.
2. **Автоответы-квалификаторы** — использует уже готовый скрипт чат-воронки (Модуль 4 `avito-listing-packaging`) как текст, отправка — через тот же API после endpoint'а.
3. **Мониторинг статусов** — возможно, не нужен отдельный API-вызов: `support.avito.ru/articles/4341` уже описывает отчёт после каждой выгрузки фида (статус, ошибки) — это часть Модуля 1, не обязательно Messenger API.

## Что нужно от владельца, чтобы уйти от `[УТОЧНИТЬ]`

1. Содержимое `avito.ru/autoload/documentation/templates` (шаблон XML) — из личного кабинета.
2. Содержимое `avito.ru/developers/api-catalog/messenger/documentation` — из личного кабинета.
3. Решение по хостингу `feed.xml` — где физически будет лежать файл, чтобы Avito мог его читать по URL.
