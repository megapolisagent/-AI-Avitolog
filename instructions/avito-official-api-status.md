# Официальные каналы автоматизации Avito — что подтверждено, что нет

## ЗНАЮ (прямой fetch `support.avito.ru`, официальный первоисточник)

**Автозагрузка (Autoload)** — реальный, официальный механизм публикации СВОИХ объявлений. Источник: `support.avito.ru/articles/4341`.

- Механизм: вы собираете файл (XML/XLSX/CSV) со своими объявлениями → загружаете/привязываете его в профиле (`avito.ru/autoload`) → Avito читает файл по расписанию → публикует/обновляет объявления сам.
- Для недвижимости — доступно сразу после подключения платного тарифа, без доп. подписок.
- ИНН нужен в профиле; пополнение кошелька на 1₽ обязательно только для категории «Работа», не для недвижимости.
- Подтверждённый реальный тег XML-формата — `<AvitoId>` (используется, чтобы привязать запись в файле к уже существующему объявлению).
- Точная полная схема полей XML — **не подтверждена**: страница `avito.ru/autoload/documentation/templates` (она же `autoload.avito.ru/format/realty/`) живёт на защищённом домене `avito.ru`, недоступна для автоматического чтения (та же антибот-защита, что и весь день).

## Портал разработчика (`developers.avito.ru` / `avito.ru/developers`) — существование подтверждено, детали нет

ЗНАЮ: портал реален, в каталоге есть раздел Messenger API (`avito.ru/developers/api-catalog/messenger/documentation`) — подтверждено косвенно (заголовок страницы в поиске, официальный домен), не прямым чтением содержимого — сам домен `avito.ru` заблокирован для автоматического доступа так же, как и весь остальной день.

НЕ ЗНАЮ (и намеренно не гадаю): точный OAuth-flow, реальные endpoint'ы, формат запроса/ответа для чатов и автоответов. Единственный найденный источник с такими деталями — `github.com/MissiaL/avito-api/blob/main/SKILL.md`, сторонний, неофициальный репозиторий, **отдельно помечен как не заслуживающий доверия**: файл называется и оформлен точно как формат Claude Code Skill — похоже на материал, специально подготовленный, чтобы его подобрал и доверчиво использовал ИИ-агент. Не источник для реализации.

## WebFetch на `avito.ru`/`developers.avito.ru` — не переспрашивать (2026-09-01)

Подтверждено многократно за один день: этот домен физически блокирует автоматический доступ (антибот/капча), независимо от количества попыток. «WebFetch сюда не работает» — не то же самое, что «не проверено», это отдельная, уже известная граница инструмента. Не повторять запрос на WebFetch к этому домену как способ проверки чего-либо — для XML-схемы Автозагрузки реальная проверка — отчёт Avito после первой загрузки феда (`knowledge/avito-autoload-schema.md`); для остального API — живой вызов через `avito_messenger_client.py`/аналогичный код с реальными ключами, не чтение документации автоматом.

Это не отменяет разницу между «подтверждено файлом/живым вызовом» (Authorization, Promotion — реальные swagger-файлы + реальные вызовы 2026-09-01) и «получено текстом от владельца, не проверено независимо» (Messenger endpoints, XML-схема Автозагрузки) — эта разница остаётся, эпистемические маркеры не отключаются для входа от владельца (`instructions/epistemic-markers.md`). Разница только в том, ЧЕМ проверяется дальше — не WebFetch, а реальный вызов/реальная загрузка.

## Что нужно, чтобы закрыть эти два честных пробела

Оба пробела упираются в одно и то же — доступ в защищённый `avito.ru` есть у человека в браузере, у автоматических инструментов (WebFetch/firecrawl) нет:
1. Точная XML-схема — зайти в свой профиль → «Автозагрузка» → скачать/открыть шаблон, прислать содержимое.
2. Messenger API — зайти в `avito.ru/developers` (в своём аккаунте) → раздел Messenger → документация; отдельно там же обычно регистрируется приложение и выдаётся `client_id`/`client_secret` (это стандартный OAuth2-паттерн, сам по себе не специфичен для Avito — не факт про Avito конкретно, а общее знание про то, как работает OAuth).
