# Архитектура: Авитолог + Трафик-менеджер

Статус: **историческая карта решения**, не актуальная структура файлов. Писалось как предложение, пока `Трафик-менеджер` был только областью знаний внутри этого репозитория. С 2026-09-01 агент реально собран как отдельный репозиторий — `../AI Traffic Manager` (свой `HOME.md`/`SOUL.md`/`DECISIONS.md`). Четыре файла из `traffic_agent/` ниже (Promotion, CPA-аукцион, CPX, CPA действия/жалобы) **перенесены туда**, здесь их больше нет — таблица ниже оставлена как есть для истории решения, не как актуальная карта `knowledge/reference/`.

Источник структуры: 13 реальных Swagger-файлов Avito Business API, загруженных владельцем 2026-08-31/09-01, распознаны по `info.title`/`info.description`/списку эндпоинтов каждого файла (не по имени файла на слово). Лежат в `knowledge/reference/<модуль>/`.

## Чек-лист роутинга — какой файл открывать в каком сценарии

Пункты 5-7 ниже (роль Трафик-менеджера) — файлы `traffic_agent/*.json`, на которые они ссылаются, перенесены в `../AI Traffic Manager/knowledge/reference/traffic_agent/`, открывать их нужно уже там, не здесь.

1. **«Хочу опубликовать карточку через фид»** → `04_feed_technical/avito-api-autoload.json` + `instructions/avito-integration-spec.md` (Модуль 1) — схема XML-тегов не подтверждена официально, см. пробел ниже.
2. **«Пришло сообщение от покупателя»** → пробел, `01_messenger/` пуст, работает пока только через `avito_messenger_client.py` + `instructions/avito-official-api-status.md`.
3. **«Проверить, не завышена ли цена лота»** → `03_analytics_market/avito-api-realty-analytics.json`.
4. **«Клиент оставил отзыв, нужен ответ»** → `02_conversion_retention/avito-api-ratings-reviews.json`.
5. **«Сколько мы платим за звонки/сообщения по лоту»** → `traffic_agent/avito-api-cpx-pricing.json` + `avito-api-cpa.json` (роль Трафик-менеджера, не Авитолога).

7. **«Похоже, звонок был спам — вернуть деньги»** → `traffic_agent/avito-api-cpa.json`, метод жалобы (`createComplaint`).

## План первого теста Автозагрузки v4 (feed.xml)

Статус: план, не выполнено — совпадает с уже открытым пунктом в `instructions/avito-integration-spec.md` («Что нужно от владельца, чтобы уйти от `[УТОЧНИТЬ]`»), не дублирует его заново, продолжает.

1. **Схема XML** — точный список тегов (`<Price>`, `<Address>` и т.д.) официально не подтверждён (антибот-защита `avito.ru` блокирует автоматическое чтение шаблона весь день 2026-09-01). Нужно: зайти в личный кабинет застройщика/агентства → «Автозагрузка» → скачать шаблон → прислать содержимое. Без этого шага собирать `feed.xml` из карточки ALIA рискованно — можно собрать по неверной схеме, и Avito отклонит файл целиком.
2. **Хостинг файла** — Avito читает `feed.xml` по стабильному публичному URL, с локального диска не увидит. Три реальных варианта, без установки нового сервера:
   - **GitHub Pages** (репозиторий `AI Avitolog` уже есть на диске, но не git-репозиторий — потребуется `git init` + подключение к GitHub, бесплатно, файл обновляется обычным commit/push).
   - **Yandex.Object Storage / S3-совместимое хранилище** — платно, но не требует GitHub, простой upload по расписанию.
   - **Существующий хостинг сайта застройщика/агентства**, если он уже есть и на него можно класть статический файл (`/feed.xml`) — самый дешёвый вариант, если такой сайт уже существует.
   Выбор — за владельцем, каждый вариант рабочий технически.
3. **Первый прогон** — один лот (ALIA, уже собран), один `<Ad>`-блок, вручную проверить в личном кабинете Avito после публикации: принял ли Avito файл, что показывает отчёт об ошибках (`support.avito.ru/articles/4341` подтверждает, что отчёт формируется после каждой выгрузки).
4. Только после успешного первого лота — расширять на все 10 карточек первой волны.
